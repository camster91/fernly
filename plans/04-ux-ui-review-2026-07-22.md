# Fernly — UX/UI Review (2026-07-22)

Visual review of camster91/fernly running on web (Expo SDK 57, RN 0.86,
React 19.2). Captured 18 screenshots across the full flow on a desktop
viewport (1280×720). This is the surface that ships to phones (390×844)
plus the laptop/desktop experience that the web bundle also serves.

**Stack as observed:** Soft pastel design system (lavender/peach/mint/rose),
serif display headings (System font, serif fallback in browser), sans-serif
body, generous whitespace. Brand identity is consistent and warm.

## TL;DR — what works, what's broken

**What works.** The visual identity is cohesive — pastel cards, generous
whitespace, serif headings, calm copy. The crisis modal is genuinely
excellent: warm, non-clinical, friction-based dismiss, AA-compliant primary
CTA on `warnDeep`, explicit "I'm an AI, you deserve human help" copy. The
TodayScreen greeting + streak strip is the strongest motivational surface in
the app. Onboarding is gentle and 5-step bounded. Tone picker with sample
quotes is a smart UX choice — users feel the personality before committing.

**What's broken.** Several real bugs surfaced during this walkthrough:

1. **`Card` has no `accessibilityRole`** — every `Pressable` card on Today,
   Practice, Profile settings list, MoodCheckIn prompt, and the empty-state
   quick-pills is invisible to VoiceOver/TalkBack. The audit flagged this
   indirectly (P1 #38 in the review), but it's empirically confirmed here:
   the browser a11y tree on the TodayScreen has ZERO clickable elements
   outside the tab bar. A VoiceOver user cannot tap the "Check-in" card.
2. **Quick-word pills on MoodCheckIn are not buttons.** Same root cause:
   `<Pressable>` without `accessibilityRole`/`accessibilityState`. VoiceOver
   announces "calm" without context that it's a selectable option.
3. **Chat history isn't rendering on web** — `expo-secure-store` on web has a
   lossy storage layer; chat messages sent during testing don't appear in
   the FlatList on reload. The session ID gets created in AsyncStorage but
   the messages themselves live in SecureStore which doesn't round-trip
   cleanly in the browser. Real users on iOS/Android won't hit this, but
   anyone testing the web build will be confused.
4. **Today's card sub-copy has a JSX error** — When a mood is logged, the
   sub reads "Tap to update — your latest entry wins for today." There's a
   stray apostrophe that the linter let through (escaped as `\'`). Renders
   fine but reads as unpolished.
5. **Insights chart axes are inconsistent.** "07/18 → 07/20" with x-axis
   07/16 → 07/22 — three plotted points on a 7-date axis. The line "starts"
   mid-axis and "ends" mid-axis, leaving the first/last dates visually
   orphaned. Either plot all 7 days (with gaps = null points) or shift the
   x-axis to match the filled range.
6. **No mobile viewport handling on web.** The web bundle renders at
   1280×720 desktop width with content left-aligned and a huge empty area
   on the right. There's no `max-width: 390px` wrapper or desktop
   alternative layout. Tablets and laptops get a stretched UI.
7. **`react` vs `react-dom` version mismatch** (lockfile drift from dependabot
   PR #32). Hard-blocked the web bundle at runtime — fixed in this session
   by bumping react-dom to 19.2.7. This is a real shipping bug: anyone
   running `npm install` against the lockfile as it was would have gotten
   a non-functional web build.

## Per-screen findings

### Onboarding 1/5 — Name input

**Visual.** "STEP 1 OF 5" eyebrow in monospace purple. Large serif heading
"What should Fernly call you?" A single rounded input with purple focus
ring. "Next" CTA as a pill, disabled until input is non-empty.

**What works.** Clear step indicator (5 dots, first active in purple,
remaining in lavender line-color). Disabled state is visually muted. The
focus ring is the accent purple — matches the brand.

**Friction point.** The placeholder text "First name" is gray on white and
renders in a small font. A user in a hurry might miss that the field is
interactive. Also: no character counter, no validation feedback (what
happens if you type "🍕"?). Probably fine for v0.

**A11y.** `accessibilityLabel="Your first name"` present (PR4 fix). The
`onSubmitEditing={next}` lets users submit via keyboard Enter — verified in
the snapshot the Next button is reachable.

**Visual score: 8/10.**

### Onboarding 2/5 — Mood self-ID

**Visual.** Seven mood pills wrapped in 3 rows: Anxious / Numb / Tired /
Hopeful / Overwhelmed / Okay / Lonely. Unselected pills are white with a
lavender border; selected turns solid lavender with white text.

**What works.** Single-select clarity — only one mood at a time. The label
"Helps Fernly meet you where you are" sets expectations.

**UX question.** Seven options is one too many. Either drop one (probably
"Okay" — feels redundant with "Tired") or split into two rows of 4 with a
better visual rhythm. Currently row 3 has only one pill ("Lonely") which
looks orphaned.

**Visual choice.** All-caps mono "STEP 2 OF 5" eyebrow is great, but at
desktop widths the input row sits at x=24-1256 — wide enough that the
single-column constraint feels tight. On mobile (390px) it'll read better.

**Visual score: 7/10.**

### Onboarding 3/5 — Goals

**Visual.** 7 emoji-prefixed goal pills in a 2-column grid. Multi-select,
max 3.

**What works.** The emojis genuinely help — 🛌 for sleep, 🧠 for quiet
thoughts, 💪 for less anxious. The "Pick up to 3" subtitle is essential
guidance; without it users might tap all 7.

**Friction point.** No visible selection counter ("0 of 3 selected") or
cap message after the third tap. The Next button just stays disabled until
at least one goal is picked, then enables — but the user has no feedback
that the third tap was the *last* allowed. Add a small "1 of 3" badge after
first selection, then "3 of 3 — pick more on your next check-in" once capped.

**A11y.** All pills have `accessibilityRole="button"` and
`accessibilityState={{ selected }}`. Verified.

**Visual score: 7/10.**

### Onboarding 4/5 — Mascot picker

**Visual.** 2×2 grid of pastel squares with one large emoji each. Default
selection is moon (lavender background). Selected state = 2px purple border.

**What works.** The 4 mascots are distinct enough at a glance. The 2x2 grid
is visually balanced. The subtitle "This is who you'll chat with" is clear
purpose.

**Friction point.** None of the 4 mascots have names — they're just emoji.
A user who doesn't immediately recognize 🌙 / 🦊 / 🐢 / 🐝 as a *personality*
choice has to guess. The accessibility labels "Choose moon as your friend
mascot" help screen reader users but the visible UI shows only the emoji.
At minimum, label each mascot with its name underneath in tiny eyebrow
text.

**Visual score: 7/10.**

### Onboarding 5/5 — Tone

**Visual.** Three tone cards in a vertical stack, each with a distinct
pastel background (lavender / peach / cream) and a sample quote in italic.
Soft is default-selected (lavender background + purple border).

**What works.** The sample quotes are the smartest UX decision in the
onboarding. Users feel the personality before committing. "your brain is
doing the thing again lol" (playful) is exactly right for the target demo.

**Friction point.** The third option "Playful" is in yellow — adjacent to
"Coming soon" tone styles. A user who picks playful might find the chat
tone too casual when they're in distress. The tone choice is sticky and
not obvious how to change later (the Settings screen is just an
`Alert.alert` placeholder per the audit). Add a "you can change this in
settings later" subtitle or surface tone change in the Profile row
immediately.

**Visual score: 9/10.**

### TodayScreen — happy path

**Visual.** Greeting "Hey Alex 👋" in serif display. Streak strip of 7
dots labelled T F S S M T W (weekday letters, not absolute dates). Three
context cards (Check-in / Today's Practice / Talk It Out). Bottom tab bar
with 5 tabs.

**What works.** The greeting hierarchy (eyebrow → name → prompt) is exactly
right. The streak strip with filled green dots + a purple "today" indicator
is visually distinct without being shouty. The three cards give the user a
clear choice of action in 30s / 4min / open-ended.

**Friction point.** "Today's already logged as 4/6" — what does 4/6 mean
to a new user? The mood picker shows 1-6 but doesn't label them (low, off,
okay, good, bright, radiant — only visible in MoodCheckIn). A user who
tapped "good" won't connect the dots. Either show the mood label
("Today's already logged as Good") or skip the numeric entirely.

**Streak strip desync.** The audit caught this: weekday letters T F S S M
T W don't align with absolute dates. If today is Wednesday, the dots should
read M T W T F S S (oldest to today). Currently they're stuck on the
weekday-of-the-app-start. The PR1/Insights fix moved Insights to MM/DD
labels; TodayScreen didn't get the same treatment.

**A11y.** The 7 streak dots have NO accessibility labels. A screen reader
user hears "dot dot dot dot dot dot dot" — no progress information. The
TodayScreen cards are also missing `accessibilityRole="button"` on the
Pressable (same Card-no-role issue as PracticeScreen).

**Visual score: 7/10.**

### TodayScreen — streak grace period

**Visual.** When today is unlogged but yesterday was, the eyebrow shows
"3-DAY STREAK · LOG TODAY TO KEEP IT" and the body reads "Log today to
keep your 3-day streak going."

**What works.** The grace logic is correct and the copy is direct without
being pressuring. The today-dot shows in lavender/accent outline (the
"loggable" state) rather than red/broken.

**Friction point.** The grace state only triggers when there are ≥1 prior
day logged. A brand-new user with no moods sees "0-DAY STREAK" and the
generic "How are you waking up today?" — no encouragement. The empty state
is too quiet; first-time users need a "Log your first mood to start a
streak" nudge.

**Visual score: 8/10.**

### ChatScreen — empty state

**Visual.** Fox mascot emoji centered. "Say the first thing. Anything. A
feeling, a worry, a 'hey.'" + "I'm here and won't judge the mess." Below
the input row, three quick-pills: "I'm anxious" / "I can't sleep" /
"Today was hard". A small 🎙 + "soon" placeholder on the input right.

**What works.** The fox emoji is friendly. The "won't judge the mess" copy
is exactly the right tone. The quick-pills lower the barrier to entry for
a user who doesn't know what to type.

**Critical bug.** The quick-pills (`QuickPill` component) are rendered as
Pressable without `accessibilityRole="button"` or `accessibilityLabel`.
Same root cause as the Card-no-role issue. Screen reader users hear "I'm
anxious, I'm anxious" (the text content) with no context that they're
tappable options.

**Critical bug.** Empty-state message bubble area renders but never
displays sent messages — the messages stay in SecureStore but the FlatList
doesn't refresh on reload. See "Chat history not rendering on web" in TL;DR.

**Visual score: 7/10.**

### ChatScreen — crisis modal

**Visual.** Semi-transparent backdrop (#2A2438 at 85% opacity) over the chat.
White card centered with a 56×56 pink circle + 💛 heart icon. "You matter."
heading, coral subtitle "Right now, please reach out to a human trained for
this." Four helpline buttons stacked: 988 (primary coral fill) /
Crisis Text Line / Find a helpline worldwide / IASP directory. Long-press
"Hold to confirm you're safe for now" with 120×8pt progress track.

**What works.** This is the best-designed screen in the app. The 988 button
is the most visually prominent element on screen — exactly what you want in
a crisis moment. The text acknowledges the AI's limitation ("I'm an AI. I
can't help in the way you deserve right now") which is ethically critical
for a wellness app. The hold-to-dismiss friction prevents accidental close.
The PR3 fixes are all visible: `accessibilityViewIsModal`, resource button
labels, hold progress visibility.

**Critical bug — primary CTA contrast.** The 988 button uses
`colors.warnDeep` (#C92A4A) as background with `colors.paper` (#FBF9F6) as
foreground. Measured contrast: 5.0:1. This clears AA-body (4.5:1) — good.
BUT the original spec/design system called for `colors.warn` (#E55D75)
which is 3.25:1 (fails AA). The PR4 introduced `warnDeep` specifically to
fix this — verify the design team signs off on the deeper rose in the
spec/HTML mock before shipping. The current ship uses `warnDeep`, which is
correct per the audit, but it's a divergence from `spec/index.html`.

**Friction point.** The other 3 helpline buttons (Crisis Text Line, Find a
helpline worldwide, IASP directory) all use the secondary outlined style
with much lower visual weight than 988. For non-US users, 988 isn't a
useful action — the "Find a helpline worldwide" button should be primary
or at least visually equal. Consider locale-aware ordering: US/CA → 988
primary; everywhere else → FindAHelpline primary.

**Visual score: 9/10.**

### PracticeScreen

**Visual.** "Practice" heading + "Pick what fits right now." subtitle. 8
exercise cards stacked vertically, each with a colored icon tile (lavender /
peach / green / yellow / rose matching the modality tag), title, blurb, and
modality pill.

**What works.** Modality tags are color-coded (CBT = lavender, ACT = mint,
BODY = peach, GROUNDING = yellow, REFLECTION = rose) — gives visual rhythm
to a long list. The emoji icons (📋 for thought record, 🍃 for box
breathing, 🌊 for defusion, etc.) add personality.

**Critical bug.** Each card's Pressable has no `accessibilityRole="button"`.
The accessibility tree shows ZERO clickable items on this screen. A
VoiceOver user can navigate to the practice list but can't tap any
exercise. This is the most-used navigation surface in the app — the bug
is blocking.

**UX question.** 8 exercises on one scroll page is a lot. Consider grouping
by modality ("Body" → box breathing, bedtime body scan / "Mind" → thought
record, defusion / etc.) with collapsible sections. Or surface "Today's
pick" as a single primary card at the top with the rest below a "see more"
expand.

**Visual score: 6/10.**

### ExerciseScreen — BoxBreathingScreen

**Visual (idle).** "BODY · 4 MIN · CYCLE 1 OF 4" eyebrow. Large lavender
bubble (220×220) with "4" + "BREATHE IN" inside. "Inhale · Hold · Exhale ·
Hold" rhythm reminder. Full-width "Begin" CTA.

**Visual (active).** Bubble expands as user inhales, "BREATHE IN" stays
inside, countdown ticks 4→3→2→1. CTA flips to "Pause".

**What works.** The bubble animation is genuinely calming. The
"4 minutes" framing is honest — no fake "just 30 seconds!" lie. The
cycle counter reminds the user this isn't infinite. The PR8 a11y labels
landed: `img "Breathe in, 4 seconds remaining"` is what screen readers
announce, plus `accessibilityLiveRegion="polite"` on the phase text means
VoiceOver reads "Hold gently" automatically when the phase changes.

**Friction point.** No audio/haptic feedback. A user with eyes closed
(legitimate use case for a breathing exercise) gets zero non-visual
cues. A soft "ding" on each phase transition or a gentle haptic pulse
would make this usable eyes-closed.

**Visual score: 9/10.**

### ExerciseScreen — stub (Thought record)

**Visual.** "CBT · 5 MIN" eyebrow. "Thought record" title + description.
Clipboard emoji (📋) with pencil (✏️). "Coming soon" disabled CTA.
"Flow builds out in build week 2." footer.

**What works.** The disabled state is honest — no fake "Begin" that bounces
back. The user knows the feature is planned. The clipboard visual is
appropriate to the CBT modality.

**Friction point.** "Build week 2" is a roadmap reference that means
nothing to an end user. Replace with "Coming in our next update" or just
drop the footer entirely. Also: the description "A classic CBT exercise.
Notice a hot thought, find the distortion, write a reframe." is good
educational copy that builds anticipation.

**Visual score: 7/10.**

### InsightsScreen

**Visual.** "THIS WEEK" eyebrow + "Your week" heading. Stat row: big "4.0
AVG MOOD" + "7 of 7 days logged". SVG line chart with purple line + dots.
"PATTERN" card explaining that patterns build after ~2 weeks.

**What works.** The big stat is unmissable. The empty-pattern card uses
anticipatory framing rather than "no data to show" — better for retention.
The chart line + dots are clearly distinguishable (purple on paper).

**Bug — chart axes desync.** The chart plots 3 days of data (07/18 →
07/20) but the x-axis shows all 7 dates (07/16 → 07/22). The result: the
line starts at 07/18 and ends at 07/20, leaving 07/16/17/21/22 visually
orphaned. Two fixes:
- Plot all 7 days, with empty positions as gaps in the line.
- Or compress the x-axis to match the filled range only.

**A11y.** The SVG has NO accessibility alternative. Screen reader users
get nothing — no "your mood averaged 4.0 this week, highest on Tuesday"
summary. PR8 didn't land a fix here; tracked as P2 #46.

**Visual score: 7/10.**

### ProfileScreen (You)

**Visual.** Circular fox avatar tile (lavender background). "Alex" name
+ "🌙 SOFT · 2 GOALS" meta line. Three stat cards: 7 ACTIVE DAYS / 7 MOODS
/ 2 GOALS. Settings list: Your mascot / Conversation tone / Your goals /
Export your data / Legal & safety.

**What works.** Stat cards have distinct pastel tints (lavender / peach /
mint). "ACTIVE DAYS" reflects real engagement (the PR6 fix). Settings rows
are simple, two-line, with chevron only on actionable items (Export, Legal).

**Critical bug.** Settings rows have NO `accessibilityRole="button"`. A
screen reader user can read "Your mascot 🦊" but can't tap to change it
(though the rows aren't actually wired to navigation either — they're
display-only per the audit finding #25). The non-actionable rows should
behave like display cards; the actionable rows (Export, Legal) should
have button roles.

**Friction point.** "Your mascot" / "Conversation tone" / "Your goals" rows
look tappable but aren't. The chevron absence is the visual cue, but
screen readers can't see chevrons. Add explicit "Edit" suffix or remove
the row entirely.

**Visual score: 7/10.**

### MoodCheckInScreen

**Visual (empty).** "GOOD MORNING CHECK-IN" eyebrow (time-aware via PR6).
"How are you, really?" + "No wrong answer. No streak loss. Just noticing."
6 emoji pills in a horizontal row. Optional card with 8 quick-word pills.
"Pick a mood first" disabled CTA.

**Visual (selected).** Selected emoji pill turns lavender with 2px purple
border and slight scale-up. "GOOD · 4/6" text appears below the row.
"Save check-in" CTA enables.

**What works.** The eyebrow reads "GOOD MORNING CHECK-IN" because my test
data was timestamped in the morning — confirming the PR6 dynamic greeting
fix works. The disabled-CTA-as-instruction pattern ("Pick a mood first")
is excellent — it tells the user exactly what to do, not just "no".

**Bug — quick-word pills have no role.** Same Pressable-no-role issue.
The 8 quick words (tired / rested / scattered / anxious / calm / wired /
tender / grateful) are not buttons in the a11y tree.

**Friction point.** The 6 emoji pills are spaced evenly across the full
screen width. On a 390px mobile viewport the spacing works; on a 1280px
desktop viewport the pills are huge and far apart, making it feel like
the row is broken. The web build needs to constrain the row to a
mobile-shaped max-width OR use a different layout for desktop.

**Visual score: 8/10.**

## Cross-cutting findings

### C1 — Pressable components missing accessibilityRole (P0)
Confirmed across TodayScreen (3 cards), PracticeScreen (8 cards),
ProfileScreen (5 settings rows), MoodCheckInScreen (8 quick-word pills),
ChatScreen (3 quick-pills). The `Card` component itself is the root
cause — it wraps `Pressable` but doesn't pass through any a11y props.
**Fix:** Add `accessibilityRole="button"` and `accessibilityLabel` props
to `Card`; require `accessibilityLabel` when `onPress` is set. Then
audit every callsite. Estimated ~30 mins.

### C2 — Mobile viewport not enforced on web (P1)
The web bundle renders the app at full desktop width. Content is
left-aligned with a 1232px-wide blank area on the right of the 1280px
viewport. This looks broken on a laptop and only "works" on mobile.
**Fix:** Either (a) wrap the root in `max-width: 414px; margin: 0 auto`
to fake a phone viewport on desktop, or (b) build a responsive layout
that uses the extra width (e.g. side rail with streak summary on
landscape tablet).

### C3 — Chart axes desync (P1)
InsightsScreen SVG line chart plots filled days only, leaving the
x-axis days visually orphaned. Either show all 7 days as a continuous
axis with gaps, or shrink the axis to match the data range.

### C4 — `react` vs `react-dom` version mismatch in lockfile (P0 ship-blocker)
Found when booting the dev server: react@19.2.7 + react-dom@19.2.3
broke the web bundle at runtime. The CI gates (typecheck, lint, format,
vitest, crisis suite) didn't catch it because none of them bundle.
**Fix:** Add `npx expo export --platform web` as a CI step. Without it,
this will recur every dependabot bump.

### C5 — Emoji legend missing on TodayScreen stat (P2)
"Today's already logged as 4/6" — what does 4/6 mean? New users won't
connect it to the mood picker. Show the mood label ("Good") instead of
the number, or include a one-time tooltip explaining the scale.

### C6 — Settings rows visually-but-not-actually tappable (P2)
"Your mascot" / "Conversation tone" / "Your goals" rows on Profile look
editable but aren't wired to navigation. Either make them tappable
(jump to a focused edit screen) or de-emphasize them so users don't
think tapping will do something.

### C7 — No audio/haptic on box-breathing phase transitions (P3)
A user with eyes closed gets no cue when the phase changes. A soft
audio chime or haptic pulse would make this usable in the real
breathing-exercise context (which is the WHOLE POINT).

### C8 — Streak strip uses weekday letters that desync across boundaries (P2)
Onboarding day-of-week misalignment: when today is Wednesday, the
strip shows T F S S M T W regardless of what calendar day each dot
actually represents. InsightsScreen fixed this with absolute MM/DD
labels; TodayScreen didn't. Use the same approach.

## What ships well

The crisis modal is the standout — clinically appropriate, visually
clear, accessibility-complete (post-PR3), and ethically honest about
AI limitations. The TodayScreen greeting hierarchy + streak grace period
is the strongest motivational surface. The onboarding tone picker with
sample quotes is the smartest "show, don't tell" pattern. The
box-breathing bubble animation is genuinely calming.

## What's not ready to ship

The Card/Pressable accessibility regression blocks VoiceOver/TalkBack
users from the most-used navigation surfaces (Today cards, Practice
list, Profile settings). This needs to land before any real-world
testing with screen reader users. The web bundle's desktop layout
also needs the mobile-viewport wrapper — currently looks broken on
anything bigger than a phone.

## Recommended ship order

1. **Card component gets `accessibilityRole`/`accessibilityLabel`** —
   single fix, blocks ~30 affected usages. Required before a11y
   testing.
2. **Web build in CI** (`expo export --platform web`) — prevents
   version-mismatch regressions like the one found today.
3. **Mobile viewport wrapper for web** — `max-width: 414px; margin: 0
   auto` for the v0 launch; revisit responsive design in v1.
4. **Insights chart axes fix** — small visual bug, high user-
   perception impact.
5. **TodayScreen streak strip → absolute MM/DD labels** — already
   fixed in Insights; mirror the approach.
6. **Quick-word pills + Settings rows a11y** — same Card pattern fix
   plus per-callsite labels.

These are small, contained changes that would close the remaining
UX gaps before any external user testing.
